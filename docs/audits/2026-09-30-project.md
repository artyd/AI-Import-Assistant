## 🟡 P2 — улучшения

**Безопасность**
- S6 JWT в `localStorage` + в URL SSE (`?access_token=` принимается на **всех** маршрутах, `auth/hook.ts:33`) → в логах Caddy; logout не отзывает токен. → короткоживущий SSE-тикет или httpOnly-cookie; `token_version` для отзыва.
- S7 Prompt injection из загруженного документа может менять контекст поставки через инструменты агента (`save_workspace_context`, `set_contract_mode`, `sort_inbox`…). Всё ограничено поставкой, удалений нет. → изменения как предложение с подтверждением в UI или хотя бы отметка источника `agent`.
- S8 Нет лимитов размера: `bodyLimit` ~26 MB на все маршруты, сообщение чата без `max`. → 1 MB по умолчанию, `.max(20000)` на сообщение.
- S9 Нет CSP/security-заголовков ни в Next, ни в Fastify/Caddy; загруженные файлы отдаются `inline` с того же origin. → CSP, `nosniff`, `frame-ancestors 'none'`, `Referrer-Policy`; файлы как `attachment`.
- S10 Любой пользователь видит email всех пользователей (`users.ts:9`); ролей нет. → `users.role`.

**Надёжность**
- R7 Vision: все окна PDF режутся и кодируются в base64 **до** лимитера → большой скан × 3 параллельные задачи = OOM. → нарезку внутрь лимитера / `p-limit`.
- R8 Отключение клиента не останавливает чат — до 15 вызовов Opus продолжают оплачиваться. → AbortController на `close`; то же на фронте (кнопка «Зупинити», F2).
- R9 Гонки DELETE+INSERT: дубли пунктов чек-листа, дубли/затирание сторон, автораскладка перетирает ручное перемещение. → advisory lock по workspace, UNIQUE + `ON CONFLICT`, `AND folder_id IS NULL`.
- R11 Миграции на каждом старте двумя процессами без блокировки; DROP/ADD CONSTRAINT берёт эксклюзивную блокировку таблиц. → `pg_advisory_lock`, условные изменения ограничений.
- R12 Символ `\u0000` из PDF не вычищается → Postgres отклоняет → файл падает и 20 раз повторно гоняет vision. → чистить в `convertToMarkdown`.
- R13 Утечка SSE-подписок Redis при раннем обрыве (`events.ts:26`); R14 нет SIGTERM в сервере; таймаут 10 мин × 5 ретраев SDK.

**Стоимость / производительность**
- C4 `uktzed_lookup_code`: каждый запрос заново суммаризирует страницу qdpro на Opus, мимо лимитера, 5–20 с. → кэш на 24 ч + Sonnet/Haiku.
- C5 Vision на PDF с хорошим текстовым слоем (~$0.02/стр.) и повтор vision при повторной загрузке того же файла. → текстовые PDF через pdf-parse (vision только для сканов/таблиц); переиспользование по `content_hash`.
- C6 Batch API (−50%) для массовых загрузок и ретраев.
- C7 Модели: извлечение на Opus 4.8 — оценить Sonnet 5.5 на эталонном наборе (нужен переход на structured outputs); чат → Opus 5.5 (−20%) с явным effort.
- C8 БД: воркер после каждого файла 3× полностью пересчитывает поставку (O(N²) на пакет); digest грузит весь JSONB ради подсчёта строк; индексы `document_extractions(file_id, extracted_at DESC)`, `messages(conversation_id, created_at)`, `pg_trgm` для поиска.

**Фронтенд**
- F2 Стрим чата не прерывается при смене разговора; поток без `done`/`error` молча обрывается (`lib/sse.ts:104-116`).
- F3 Истёкшая сессия выглядит как пустые данные (30+ `catch {}`) → глобальная обработка 401.
- F4 Загрузка: нет проверки размера до отправки, нет прогресса, пакеты по 40 файлов до ~800 MB, `alert()`.
- F5 Долгие чаты тормозят: каждое нажатие клавиши и токен перерисовывают и заново парсят Markdown всех сообщений → `React.memo`, вынести ввод в `Composer`.
- F6 `api()` падает на HTML-ошибке прокси; iframe превью без `sandbox`; коды ошибок бэкенда (`rate_limited`) показываются пользователю как есть.
- F7 E2E не покрывают: успешный/неуспешный вход, стриминг чата, событие `file_status`, 401 посреди сессии.

## Что сделано хорошо
- Проверка владельца (`getOwnedWorkspace`/`getOwnedCollection`) везде, 404 вместо 403.
- Весь SQL параметризован; zod на входе; bcrypt cost 12.
- BYOK-ключи — AES-256-GCM, наружу только маска; адреса провайдеров зашиты.
- Postgres/Redis/logist-mcp без внешних портов; backend/frontend только на 127.0.0.1.
- Markdown в UI без raw HTML, `javascript:`-ссылки блокируются; тяжёлая карта грузится лениво.
